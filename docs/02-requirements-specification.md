# awase 要件定義書

この文書は2026-10-31に作成し、確定版としています。要求の出典は`01-requirements-analysis.md`です。

## 1 用語

| 用語 | 意味 |
|---|---|
| イベント | 日程を決めたい集まりです。タイトル、メモ、候補を持ちます |
| 候補 | イベントの候補日時です。「11/3(月) 19:00〜」のような自由な文字列で表します |
| 回答 | 参加者1名分の出欠です。名前、候補ごとの出欠、コメントを持ちます |
| 出欠 | 候補ごとの○、△、×のいずれかです |
| 共有アカウント | 全員が使う1組のユーザー名とパスワードです |

## 2 機能要件

### FR-01 ログイン

- 利用者は共有アカウントのユーザー名とパスワードでログインします。
- ログインに成功すると、awaseはセッションを発行し、ログイン前に開こうとしたページへ移動させます。移動先がない場合はイベント一覧へ移動させます。
- 移動先はawase内のパスに限ります。外部のURLや`//`で始まるパスを指定された場合、awaseはイベント一覧へ移動させます。
- ログインしていない利用者が`/login`、`/healthz`、`/static/`以外を開くと、awaseはログイン画面へ移動させます。移動先として元のページを覚えるのは、GETの要求の場合だけです。

### FR-02 ログアウト

- 利用者はログアウトできます。awaseはそのセッションを無効にします。

### FR-03 ログイン失敗の制限

- 同じIPアドレスからのログイン失敗が15分間に10回に達すると、awaseはその後15分間、そのIPアドレスからのログインを拒否し、HTTPステータス429を返します。IPv6は先頭64ビットが同じアドレスをまとめて1つと数えます。

### FR-04 共有アカウントの設定

- 運用者は`awase passwd`コマンドで共有アカウントのユーザー名とパスワードを設定します。パスワードは標準入力から読みます。
- 共有アカウントは常に1つです。コマンドを再実行すると、awaseは共有アカウントを置き換え、すべてのセッションを無効にします。
- ユーザー名は前後の空白を取り除いて1〜64文字とし、取り除いた値を保存します。パスワードは12文字以上とします。パスワードは標準入力の行末の改行(LFとCRLF)だけを取り除き、空白は取り除きません。
- 共有アカウントを設定するまで、誰もログインできません。

### FR-05 イベント一覧

- ログイン後のトップ画面にイベントを新しい順に並べます。各行にタイトル、候補の数、回答の数、最終更新日時を出します。

### FR-06 イベント作成

- 利用者はタイトル、メモ、候補を入力してイベントを作ります。候補は複数行の入力欄に1行1件で書きます。
- 作成に成功すると、awaseはそのイベントのページへ移動させます。

### FR-07 イベント表示

- イベントのページは、候補を行、回答者を列とする表を出します。各セルは○、△、×のいずれかです。後から追加した候補で回答者がまだ出欠を付けていないセルは「−」を出します。
- 各候補の行に○、△、×の人数を出します。
- ○の人数が最も多い候補の行を強調表示します。○が1人もいない場合は強調しません。
- 表の下に回答者ごとのコメントを出します。

### FR-08 回答の入力

- 利用者は名前、候補ごとの出欠、コメントを入力して回答します。すべての候補について出欠を選ぶ必要があります。
- 同じ名前の回答も受け付けます。
- 送られた候補が、そのイベントの候補と一致しない回答は受け付けません。

### FR-09 回答の編集

- 利用者は表の回答者名を選び、その回答の名前、出欠、コメントを変更できます。共有アカウントなので、誰の回答でも変更できます。

### FR-10 回答の削除

- 利用者は回答を削除できます。

### FR-11 イベントの編集

- 利用者はタイトルとメモを変更できます。
- 利用者は候補を追加できます。追加の入力は作成時と同じく1行1件です。既存の候補と追加分の合計は50件までです。
- 利用者は候補を1件ずつ削除できます。候補を削除すると、その候補に付いた出欠も消えます。最後の1件の候補は削除できません。

### FR-12 イベントの削除

- 利用者はイベントを削除できます。そのイベントの候補と回答も消えます。

## 3 入力の制約

文字数はUnicodeのコードポイント単位で数えます。前後の空白は取り除いてから数え、取り除いた値を保存します。

| 項目 | 制約 |
|---|---|
| タイトル | 1〜100文字 |
| メモ | 0〜1000文字 |
| 候補1件 | 1〜100文字。空行は無視します |
| 1イベントの候補の数 | 1〜50件 |
| 名前 | 1〜30文字 |
| コメント | 0〜200文字 |

制約に違反した入力に対し、awaseは入力内容を保ったまま同じ画面を出し、違反した項目ごとに理由を表示します。

## 4 非機能要件

### NFR-01 性能

- 5名程度が同時に操作しても、各画面の応答はホスト上の計測で500ミリ秒以内に返します。

### NFR-02 セキュリティ

- 通信はCloudflareでHTTPSにします。オリジンはCloudflare Origin CA証明書を使い、SSLモードはFull(strict)とします。
- パスワードはscryptでハッシュ化して保存します。
- セッションCookieはHttpOnly、Secure、SameSite=Laxを付け、有効期間は30日とします。Secureは既定で付けます。DBにはセッショントークンのSHA-256ハッシュだけを保存します。
- 状態を変える要求は、別のオリジンから送られたものを拒否します。
- 画面への出力はすべてHTMLエスケープします。
- SQLはすべてプレースホルダを使います。
- 応答にセキュリティヘッダを付けます。
- 秘密情報をリポジトリに置きません。

### NFR-03 Cloudflareのガード

- オリジンの443番と80番は、CloudflareのIPアドレス範囲からの接続だけを受け付けます。
- awaseのホスト名に日本以外から来た要求を、Cloudflareで遮断します。
- `/login`への要求が同じIPアドレスから10秒間に10回を超えた場合、Cloudflareは続く10秒間、そのIPアドレスからの要求を遮断します。

### NFR-04 feedflowとの同居

- awaseのコンテナが止まっていても、feedflowは応答を続けます。
- awaseの設定の誤りで、feedflowの入口となるnginxが止まってはいけません。
- awaseのメモリ使用量に上限を設け、上限を超えた場合も停止するのはawaseだけとします。停止したawaseは自動で再起動します。
- 5名程度が同時にログインしても、awaseのメモリ使用量は上限を超えません。

### NFR-05 データの保全

- データはSQLiteの1ファイルに保存し、EBS上に置きます。
- バックアップは取りません。EBSが壊れた場合と、feedflowのEC2とEBSを削除した場合は、データが失われます。これは利用者の判断です。

### NFR-06 品質

- 単体テストのカバレッジはモジュール全体で80%以上とします。
- ミューテーションテストは、変異後にビルドできないものを除き、全件KILLEDとします。
- すべての関数のCRAP値を15未満とします。
- ミューテーションテストの作業領域は、正常終了でも中断でも消します。作業領域が残っている場合、品質ゲートは失敗します。

### NFR-07 保守性

- ドメイン、サービス、永続化、HTTPの各層はインターフェースで依存し、組み立ては起動処理で行います。

### NFR-08 画面

- PCとスマートフォンの最新のブラウザで使えます。画面幅に合わせて表の配置を変えます。
- 日時は日本時間で表示します。

### NFR-09 運用

- ログは構造化ログとして標準出力に出します。
- 稼働確認用に`/healthz`を用意します。

## 5 受け入れ条件

| 要件 | 受け入れ条件 |
|---|---|
| FR-01 | 正しい資格情報でログインすると、ログイン前に開こうとしたイベントのページが出ます。誤った資格情報では、ログイン画面に失敗の表示が出ます |
| FR-01 | `next`に`https://example.com`や`/%09/example.com`を渡してログインすると、イベント一覧へ移動します |
| FR-02 | ログアウト後に以前のCookieでイベント一覧を開くと、ログイン画面へ移動します |
| FR-03 | 同じIPアドレスから10回失敗すると、11回目は正しい資格情報でも429が返ります。IPv6では同じ/64の別のアドレスからも429が返ります |
| FR-04 | `awase passwd`の再実行後、以前のセッションのCookieはログイン画面へ移動させられます。共有アカウントを設定する前は、どの資格情報でもログインできません |
| FR-05 | 一覧が新しい順に並び、各行に候補の数、回答の数、最終更新日時が出ます |
| FR-06〜FR-08 | 候補を3件持つイベントを作り、2名が回答すると、表に2列と候補ごとの人数が出ます |
| FR-07 | ○の人数が最多の候補の行が強調されます |
| FR-08 | 別のイベントの候補を混ぜた回答と、候補が欠けた回答は保存されず、422が返ります |
| FR-09、FR-10 | 回答の変更と削除が表に反映されます |
| FR-11 | 候補を追加すると、既存の回答者のその候補のセルは「−」になります。候補を削除すると、その行と出欠が消えます。合計51件になる追加と、最後の1件の削除は拒否されます |
| FR-12 | イベントを削除すると、一覧から消え、そのURLは404を返します |
| 入力の制約(3章) | 101文字のタイトルでは作成されず、理由が表示されます |
| NFR-02 | 別オリジンからのPOSTは403を返します |
| NFR-03 | オリジンのIPアドレスへ直接HTTPSで接続するとタイムアウトします。`GET /login`へ10秒間に続けて要求すると、途中から429が返ります |
| NFR-01 | ホストで一覧とイベントの画面へ5件同時に要求し、すべて500ミリ秒以内に応答します |
| NFR-04 | awaseのコンテナを止めた状態で、feedflowのURLが応答し、`nginx -t`が成功します。壊れた設定を配送すると元の設定に戻ります。誤った資格情報のログインを10件同時に送っても、awaseは止まりません |
| NFR-06 | 品質ゲートとミューテーションテストが成功し、作業領域が残っていません |
