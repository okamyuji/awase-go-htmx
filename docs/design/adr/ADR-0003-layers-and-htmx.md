# ADR-0003 インターフェースで層を分け、hx-boostで画面を作る

ステータス 採用

## 状況

利用者は、ドメインモデルがある場合に全層をDIで疎結合にするよう指定しました。画面はGoのテンプレートとhtmxで作ります。

## 決定

- 層は`domain`、`port`、`service`、`store`、`auth`、`handler`に分けます。`port`にリポジトリとサービスのインターフェースを置き、具体的な型の組み立ては`cmd/awase`だけで行います。
- 画面は`body`に`hx-boost="true"`を付け、サーバーは常に画面全体のHTMLを返します。
- htmxは2.0.11を使い、`responseHandling`を設定して4xxと5xxの応答も画面に反映します。`responseHandling`は2.0で入った設定です。

## 理由

インターフェースで層を分けると、ハンドラのテストにサービスの偽物を、サービスのテストにリポジトリの偽物を差し込めます。画面の一部だけを返す作りにすると、部分テンプレートと経路が画面ごとに増えます。`hx-boost`なら画面ごとのテンプレートだけで、ページ遷移をhtmxの要求に置き換えられます。JavaScriptが動かない場合も、同じ経路が通常のフォームとして動きます。

## 結果

1回の操作で返すHTMLは画面全体の分だけ大きくなります。利用者は5名程度なので、この差は問題になりません。
