# ADR-0006 品質ゲートとミューテーションの残骸の扱い

ステータス 採用

## 状況

利用者は、カバレッジ80%以上、ミューテーションテストの全件KILLED、CRAP値15未満を求めました。ミューテーションテストが作る複製の残骸は、テスト後に必ず消えるように仕組みで強制します。

## 決定

- CRAP値の計算とミューテーションの判定は、event-streaming-valkeyの`scripts/crap.sh`と`scripts/mutation.sh`を流用します。
- ミューテーションテストの道具はgremlins v0.6.0とします。
- `scripts/mutation.sh`は`TMPDIR`をリポジトリの外の`${XDG_CACHE_HOME:-$HOME/.cache}/awase-mutation`に向け、`trap`で終了と割り込みのたびに削除します。
- `scripts/check-mutation-residue.sh`を品質ゲートとpre-commitで実行し、作業領域か結果ファイルが残っていれば失敗させます。

## 理由

gremlinsは`os.TempDir()`の下にモジュール全体を除外なしで複製します。作業領域をモジュールの中に置くと、作業領域自身を複製し続けて失敗するため、モジュールの外に置きます。`TMPDIR`を1か所に集めれば、削除の対象を1つのディレクトリに絞れます。`SIGKILL`のように`trap`で受けられない終了に対しては、残骸の検出で次のコミットを止めます。gremlinsの効率の閾値は、テストが届かない変異と時間切れの変異を分母に入れません。全件KILLEDの判定に使えないため、結果のJSONをjqで読んで判定します。gremlinsは中断されると終了コード0で終わり、JSONを書きません。そのため、JSONがない場合も失敗とし、シグナルを受けたスクリプトは0以外で終わります。

## 結果

ミューテーションテストは時間がかかるため、品質ゲートには入れず、実装の最後に手動で実行します。残骸の検出だけは毎回のコミットで動きます。
